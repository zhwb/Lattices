1. 为什么需要 BKZ？——从 LLL 的局限说起

在讲 BKZ 之前，我们先回顾一下 LLL。LLL 是 1982 年提出的格基约化算法，它的核心操作非常简单：

LLL 在做什么

LLL 每次只看相邻的两个基向量 (bᵢ, bᵢ₊₁)。如果它们不满足 Lovász 条件（即交换后第一个向量会变短），就交换它们。然后做 size reduction（把 bᵢ₊₁ 中 bᵢ 的分量减掉）。

这就像整理书架：你只比较相邻的两本书，如果左边的比右边的高就交换，反复扫几遍，书架就基本整齐了。

LLL 的问题

LLL 很快（多项式时间），但质量不够好。它的近似因子是 2^{(n-1)/2}——在高维下，第一个基向量可能比真正的最短向量长指数倍。

为什么？因为 LLL 只看相邻两个向量，它看不到全局。可能有一个很短的向量藏在 5 个基向量的组合里，但 LLL 永远不会同时考虑这 5 个向量。

核心矛盾：LLL 快但质量差，KZ（Korkine-Zolotarev，每次对整个前缀求 SVP）质量好但慢到不可行（n 维需要 n 次全维 SVP）。BKZ 就是在两者之间找平衡——用一个可调的块大小 β 来控制"看多宽"。

从 LLL 到 KZ 的光谱

LLL (β=2) ←——— BKZ (2 < β < n) ———→ KZ (β=n)

β=2 时 BKZ 退化为 LLL，β=n 时 BKZ 退化为 KZ。β 越大，质量越好，但越慢。这就是 BKZ 最核心的设计哲学：用一个参数统一了速度和质量的 trade-off。

2. BKZ 的核心思想：从"看两个"到"看一个块"

2.1 块（Block）是什么？

BKZ 引入了一个大小为 β 的滑动窗口。在每一步，它取出连续的 β 个基向量构成的子格：

B_{[κ, κ+β-1]} = (b_κ, b_{κ+1}, ..., b_{κ+β-1})

然后对这个子格（在投影空间中）求最短向量（SVP），把找到的短向量插回基中，再做 size reduction。

通俗类比

如果说 LLL 是"每次只比较相邻两本书"，那 BKZ 就是"每次抽出连续 β 本书，在这 β 本里找到最短的那本放到最前面，然后窗口向右滑动一格"。

β 越大，你每次考虑的书越多，就越有可能发现"其实这 β 本组合起来有一本更短的"。但找 β 本书里的最短向量也越难。

2.2 为什么在投影空间中求 SVP？

这是 BKZ 最关键的技术细节。BKZ 不是直接对子格 B_{[κ,κ+β-1]} 求 SVP，而是对它的投影求 SVP：

π_κ(L) ∩ span(b_κ*, ..., b_{κ+β-1}*)

也就是说，把前 κ-1 个基向量张成的子空间"去掉"，只看剩余的投影。这样做的原因是：

  • 前 κ-1 个向量已经被前面的步骤约化好了，不应该被破坏
  • 在投影空间中求 SVP，找到的短向量插回位置 κ 后，不会影响前面已经约化好的部分
  • 这保证了算法的渐进性：每一步都在"改善"基，而不是"打乱重来"

2.3 一次 BKZ Tour（遍历）

BKZ 的一次完整遍历（tour）就是：窗口从 κ=0 滑动到 κ=n-1，每个位置都做一次 SVP + 插入 + size reduction。一次 tour 结束后，基的质量通常会改善。然后重复 tour，直到基不再变化（收敛）。

关键概念：
  • SVP Oracle：BKZ 内部调用的"求最短向量"的子程序。可以是枚举、筛法，甚至是另一个更小的 BKZ。
  • Tour：窗口从左滑到右的一次完整遍历。
  • 收敛：连续几次 tour 后基不再变化，此时称基是 BKZ-约化的。

3. 原始 BKZ：Schnorr-Euchner (1994)

1994 年，Schnorr 和 Euchner 提出了原始 BKZ 算法。它的结构非常简洁：

3.1 完整算法步骤

1
预处理
对整个基做 LLL 约化，计算 Gram-Schmidt 信息
2
开始一次 Tour
窗口位置 κ 从 0 开始
3
局部 LLL
对当前块 [κ, κ+β-1] 做一次 LLL（保持块内基本有序）
4
调用 SVP Oracle
在投影空间 π_κ 中，对块 [κ, κ+β-1] 求最短向量 v
5
插入短向量
把 v 插入到位置 κ（替换原 b_κ），然后对 κ+1 到 κ+β-1 做 size reduction
6
滑动窗口
κ ← κ+1，如果 κ ≤ n-β 回到步骤 3
7
检查收敛
如果这次 tour 中基发生了变化，回到步骤 2 开始下一次 tour；否则结束

3.2 原始 BKZ 的局限

  • SVP 用完整枚举：没有剪枝，β 超过 30 就非常慢
  • 无块内预处理：每次直接对原始块求 SVP，块内基质量可能很差
  • 固定轮数：通常跑 8-16 轮，可能在已经收敛后还在浪费时间
  • 安全估计偏乐观：因为实际运行的 β 比理论小，导致密码参数被低估

4. BKZ 2.0：三大改进 (Chen-Nguyen 2011)

2011 年，Chen 和 Nguyen 提出了 BKZ 2.0，这是至今仍在广泛使用的标准版本。它引入了三项关键改进，直接改写了格密码的安全参数估计。

4.1 改进一：极端剪枝枚举

原始 BKZ 用完整枚举求 SVP，BKZ 2.0 改用极端剪枝枚举（Extreme Pruning）。

核心思想：不追求 100% 找到最短向量，而是把成功概率压到很低（如 1%），让单次枚举极快，然后重复多次。由于期望时间 = 单次时间 / 概率，而极端剪枝下单次时间的下降幅度远超概率的下降幅度，总体反而更快。

理论上，极端剪枝相比完整枚举获得 2^{n/2} 的指数级加速。这让 BKZ 的实用块大小从 β≈20-30 提升到了 β≈40-60。

4.2 改进二：块内预处理

在对大小为 β 的块调用 SVP 枚举之前，先对这个块做一次更小的 BKZ（块大小为 β/2 或更小）。

类比

就像打扫房间：先粗略整理一遍（小 BKZ），再仔细清扫每个角落（枚举）。预处理花了一些时间，但让后续枚举的搜索空间小很多，总体更快。

这是一个递归的思想：大 BKZ 调用小 BKZ，小 BKZ 调用更小的 BKZ，直到块大小小到用 LLL 或直接枚举。

4.3 改进三：提前终止

原始 BKZ 跑固定轮数。BKZ 2.0 监控基的质量（如第一个向量的长度、GSO 向量长度的几何平均），当连续几轮没有显著改善时就停止。

这避免了在已经收敛的基上浪费时间，尤其在高维下节省明显。

4.4 BKZ 2.0 的影响

BKZ (1994)

  • 实用 β ≤ 30
  • 安全估计偏乐观
  • 无预处理
  • 固定轮数

BKZ 2.0 (2011)

  • 实用 β ≈ 40-60
  • 更准确的安全估计
  • 块内递归预处理
  • 提前终止
  • 至今仍是工业标准

5. DeepBKZ：用深度插入替代普通 LLL

5.1 什么是 DeepLLL？

普通 LLL 只交换相邻的向量 (bᵢ, bᵢ₊₁)。而 DeepLLL（LLL with Deep Insertions）允许把一个向量插入到任意前面的位置，而不仅是相邻交换。

类比

普通 LLL 像冒泡排序：只能交换相邻元素。DeepLLL 像插入排序：可以把一个元素直接插到前面任意位置。在某些情况下，插入排序比冒泡排序效率高得多。

5.2 DeepBKZ 的设计

DeepBKZ 的核心改动很简单：把 BKZ 中的"局部 LLL"替换为"局部 DeepLLL"。

具体来说，在每次 SVP 调用之后，不是只做普通的 size reduction，而是尝试把找到的短向量尽可能深地插入到前面的位置——只要插入后 GSO 向量长度的乘积（势函数）下降，就继续往前插。

5.3 为什么 DeepBKZ 更好？

  • 更激进的约化：深度插入可以一次性把短向量放到更前面的位置，加速收敛
  • 更好的基质量：在相同 β 下，DeepBKZ 输出的基通常比 BKZ 2.0 更短
  • 数学上更优雅：DeepBKZ 有更清晰的势函数下降分析
注意：DeepBKZ 的"Deep"指的是深度插入（Deep Insertion），不是"更深的网络"或"深度学习"。它是一个纯经典的格算法改进。

5.4 变体：Self-Dual DeepBKZ

近年来还有 Self-Dual DeepBKZ 等变体，结合了自对偶策略（交替约化原格和对偶格）和深度插入，在某些格上表现更好。

6. Progressive BKZ：从小到大逐步加块

6.1 动机：为什么不直接用大 β？

假设你想用 β=60 的 BKZ 约化一个基。直接从 β=60 开始会很慢，因为初始基的质量很差，SVP 枚举的搜索空间很大。

Progressive BKZ（渐进式 BKZ）的思想是：先用小块预处理，再逐步增大块大小。

6.2 具体策略

1
从 β=2（即 LLL）开始
快速得到一个基本约化的基
2
增大到 β=10，跑几轮
基的质量进一步提升
3
增大到 β=20，跑几轮
此时基已经比较好了
4
继续增大到目标 β=60
因为基已经被小块预处理过了，大块的 SVP 搜索空间小很多

6.3 为什么更快？

关键洞察：SVP 的时间是块大小的指数函数。如果用小 β 预处理能让大 β 的 SVP 搜索空间缩小哪怕一点点，由于指数效应，总时间可能大幅减少。

实验表明，Progressive BKZ 比直接用目标 β 的 BKZ 2.0 快 2-5 倍，且最终基质量相同。

6.4 块大小策略

不同的 Progressive BKZ 变体使用不同的块大小递增策略：

  • 线性递增：β = 2, 3, 4, ..., β_max（最简单）
  • 阶梯递增：β = 10, 20, 30, ..., β_max（每档跑固定轮数）
  • 自适应递增：根据基质量改善情况决定何时增大 β（Aono et al. 2016 的 Improved Progressive BKZ）

现代实现（如 fplll 的 wrapper）会自动选择最优的块大小序列，用户无需手动调参。

7. 其他重要变体

7.1 Slide Reduction (Gama-Nguyen 2008)

Slide Reduction 是 BKZ 的一个理论竞争者。它把基分成大小为 β 的块，然后在相邻块之间做"滑动"约化。

  • 理论优势：近似因子比 BKZ 好（更短的输出向量）
  • 实践劣势：实验中 consistently 比 BKZ 慢，且实现复杂
  • 现状：fplll 中有实现，但很少作为首选

7.2 Self-Dual BKZ (SD-BKZ, MW16)

SD-BKZ 交替进行前向扫描（从左到右）和后向扫描（从右到左，在对偶格上）。

  • 前向扫描在原格上做 SVP，改善短向量
  • 后向扫描在对偶格上做 SVP，改善长向量（对偶格的短向量对应原格的"好的"长向量）
  • 只在精确 β 维调用 SVP（BKZ 在边界处块会变小）
  • 实验中与 BKZ 2.0 质量接近，但某些格上略好

7.3 Pump-N-Jump BKZ (G6K, 2019)

这是 G6K 库提出的现代 BKZ 变体，核心是用筛法替代枚举作为 SVP Oracle，并引入了 Pump 机制。

Pump 机制：
  1. Pump down：从低维开始，逐步把筛法数据库扩展到高维，每扩展一维就做一次筛法
  2. Jump：在高维找到短向量后，窗口向前跳跃多格（而不是 BKZ 的一格），加速遍历
Pump-N-Jump BKZ 在高维（β > 60）下比纯枚举的 BKZ 2.0 快得多，是目前创纪录的格基约化方法。

小 β (10-25)

  • 运行时间：秒级到分钟级
  • 质量：比 LLL 好，但有限
  • 适用：CTF 题目、粗略约化、预处理
  • SVP Oracle：枚举足够快

中 β (30-50)

  • 运行时间：分钟到小时级
  • 质量：显著优于 LLL
  • 适用：密码分析、SVP 挑战
  • SVP Oracle：需要剪枝枚举

大 β (60-80)

  • 运行时间：小时到天级
  • 质量：接近理论极限
  • 适用：高维格攻击、安全参数估计
  • SVP Oracle：Progressive + 极端剪枝

超大 β (>80)

  • 运行时间：天到月级（需集群）
  • 质量：当前计算极限
  • 适用：破纪录攻击、学术研究
  • SVP Oracle：G6K 筛法 + Pump

10. 最简 Python 代码实现

下面是一个教学用的 BKZ 最简实现。它使用上一篇讲过的枚举作为 SVP Oracle，省略了剪枝、浮点优化等工程细节，但完整保留了 BKZ 的核心逻辑。

10.1 辅助函数：LLL 和 Size Reduction

import numpy as np

def gram_schmidt(B):
    """Gram-Schmidt 正交化，返回 Bstar 和 mu"""
    n = B.shape[0]
    Bstar = np.zeros_like(B, dtype=float)
    mu = np.zeros((n, n), dtype=float)
    for i in range(n):
        Bstar[i] = B[i].astype(float)
        for j in range(i):
            mu[i, j] = np.dot(B[i], Bstar[j]) / np.dot(Bstar[j], Bstar[j])
            Bstar[i] -= mu[i, j] * Bstar[j]
    return Bstar, mu

def size_reduce(B, mu, k):
    """对第 k 个向量做 size reduction（用前面的向量）"""
    for j in range(k-1, -1, -1):
        if abs(mu[k, j]) > 0.5:
            q = int(round(mu[k, j]))
            B[k] -= q * B[j]
            # 更新 mu
            for i in range(j):
                mu[k, i] -= q * mu[j, i]
            mu[k, j] -= q
    return B, mu

10.2 BKZ 核心实现

def bkz_reduction(B, beta, max_tours=8, verbose=False):
    """
    最简 BKZ 实现（教学版）。
    B: n×m 格基矩阵（n 行向量）
    beta: 块大小
    返回: 约化后的基
    """
    n = B.shape[0]
    B = B.copy().astype(float)
    Bstar, mu = gram_schmidt(B)

    # 先用 LLL 预处理（简化版：只做 size reduction + 相邻交换）
    from fpylll import IntegerMatrix, LLL # 实际中用 fplll 的 LLL
    # 这里简化：假设输入已经是 LLL 约化的

    for tour in range(max_tours):
        changed = False

        for kappa in range(n - 1):
            # 块的结束位置
            block_end = min(kappa + beta, n)
            block_size = block_end - kappa

            if block_size < 2:
                continue

            步骤1: 对块做局部 LLL（简化：size reduction）
            for k in range(kappa+1, block_end):
                B, mu = size_reduce(B, mu, k)

            步骤2: 在投影空间中对块求 SVP
            提取投影后的块基
            block_B = Bstar[kappa:block_end].copy()
            # 调用枚举求 SVP（使用上一篇的 enumerate_svp 函数）
            v_coeffs, v_norm = enumerate_svp(block_B)

            if v_coeffs is None:
                continue

            步骤3: 把短向量从投影空间还原回原空间
            v = sum(v_coeffs[i] * B[kappa+i]) （但要考虑投影）
            简化：直接用系数组合块内向量
            v = np.zeros_like(B[0])
            for i in range(block_size):
                v += v_coeffs[i] * B[kappa + i]

            步骤4: 检查是否比当前 b_kappa 短
            current_norm = np.dot(Bstar[kappa], Bstar[kappa])
            if v_norm >= current_norm - 1e-10:
                continue  # 没有改善，跳过

            步骤5: 插入短向量到位置 kappa
            # 把 v 作为新的 b_kappa，后面的向量后移
            new_B = np.vstack([B[:kappa], v.reshape(1, -1), B[kappa:block_end-1], B[block_end:]])
            B = new_B
            changed = True

            # 重新计算 GSO（简化：全量重算）
            Bstar, mu = gram_schmidt(B)

            步骤6: 对 kappa+1 到 block_end-1 做 size reduction
            for k in range(kappa+1, min(kappa+beta, n)):
                B, mu = size_reduce(B, mu, k)

        if verbose:
            first_norm = np.sqrt(np.dot(Bstar[0], Bstar[0]))
            print(f"Tour {tour+1}/{max_tours}, ||b1||={first_norm:.4f}, changed={changed}")

        if not changed:
            break  # 提前终止（BKZ 2.0 改进）

    return B

注意：这是教学实现，有几个简化：
  • SVP Oracle 用的是无剪枝枚举，高维会很慢
  • 没有块内预处理（BKZ 2.0 改进）
  • 没有极端剪枝
  • GSO 每次全量重算，工业实现用增量更新
  • 没有处理浮点精度问题
但核心逻辑——滑动窗口、投影 SVP、插入短向量、size reduction、多轮 tour、提前终止——是完全一致的。

11. 工业界使用的库

实际使用中，你几乎不会自己实现 BKZ。下面是目前最主流的格基约化库：

fplll
C++

最权威的格基约化库。实现了 LLL、BKZ、BKZ 2.0（极端剪枝+预处理+提前终止）、Slide Reduction、Self-Dual BKZ。包含自动选择最优策略的 wrapper。是 SageMath 的默认后端。

GitHub: fplll/fplll

fpylll
Python

fplll 的 Python 封装。可直接调用 BKZ、BKZ 2.0，还提供了 Python 版的 BKZ 2.0 实现方便研究和修改。

安装: pip install fpylll

G6K
C++ / Python

General Sieve Kernel。实现了 Pump-N-Jump BKZ，用筛法替代枚举作为 SVP Oracle。在高维（β>60）下比 fplll 快得多，多次打破 SVP 挑战纪录。

GitHub: fplll/g6k

NTL
C++

Victor Shoup 开发的数论库，包含 BKZ 实现（支持剪枝）。历史最悠久，Schnorr-Hörner 剪枝最早在 NTL 中实现。

官网: shoup.net/ntl

SageMath
Python

开源数学软件，内置 fplll 和 NTL。一行代码 A.BKZ(block_size=40) 即可完成 BKZ 约化，是研究和教学最方便的工具。

官网: sagemath.org

g6k-rs
Rust

G6K 的 Rust 重实现，提供 LLL/BKZ、Pump-N-Jump BKZ、筛法。内存安全，适合需要现代工具链的项目。

Crates: g6k-rs

12. 总结与延伸阅读

核心要点回顾

  1. BKZ 是什么：用大小为 β 的滑动窗口，在每个窗口内求 SVP，把短向量插回基中，反复遍历直到收敛
  2. 为什么需要 BKZ：LLL 只看相邻两个向量，质量不够；KZ 看全部，太慢；BKZ 用 β 在两者间取平衡
  3. 投影 SVP：BKZ 在投影空间中求 SVP，保证不破坏前面已约化的部分
  4. BKZ 2.0 三大改进：极端剪枝枚举、块内预处理、提前终止——至今工业标准
  5. DeepBKZ：用深度插入（DeepLLL）替代普通 LLL，更激进的约化
  6. Progressive BKZ：从小到大逐步增大 β，比直接用大 β 快 2-5 倍
  7. Pump-N-Jump BKZ：用筛法替代枚举，高维最快，G6K 实现
  8. β 的选择：小 β 快但质量差，大 β 慢但质量好；密码安全估计基于 BKZ 2.0 的 β

三篇指南的关系

这三篇指南构成了格基约化的完整知识体系：

  1. 枚举（Enumeration）：BKZ 内部的 SVP Oracle 之一，低维最快
  2. 筛法（Sieving）：BKZ 内部的 SVP Oracle 之二，高维最快
  3. BKZ 系列：把 SVP Oracle 组织成格基约化的框架

理解了这三者，就理解了现代格基约化的全部核心技术。
