1. 为什么需要筛法？——从淘金热说起

上一篇我们讲了枚举（Enumeration）：它像一个耐心的矿工，把搜索空间组织成树，一层一层地挖，保证能挖到金子，但挖得很慢——时间复杂度是 2^{Θ(n log n)}，维度高了根本挖不动。

筛法（Sieving）则完全不同。它的灵感来自"淘金"：

通俗类比

想象你在一条满是泥沙的河里淘金。你不会一粒一粒地检查每颗沙子（那是枚举）。相反，你会：

  1. 大量取样：舀起一大盆河沙（随机采样很多格向量）
  2. 粗筛：用筛子晃一晃，让大颗粒（长向量）和小颗粒（短向量）分开
  3. 碰撞提纯：把两颗沙粒放一起磨一磨（向量相加/相减），如果磨出了更小的颗粒就保留
  4. 反复迭代：不断取样、筛、碰撞，直到盆里剩下的都是金粒（最短向量）

筛法不保证每一步都精确，但通过大量随机样本和反复"碰撞"，能以 2^{O(n)} 的时间找到最短向量——在高维下比枚举快得多！

枚举 vs 筛法：核心区别

枚举 Enumeration

  • 确定性算法（搜完一定找到）
  • 多项式空间（只存当前路径）
  • 时间 2^{Θ(n log n)}
  • 低维（β≤60）更快
  • 像"深度搜索"，一条路走到黑

筛法 Sieving

  • 概率性算法（启发式，实践中总有效）
  • 指数空间（需要存大量向量）
  • 时间 2^{0.292n}（最佳）
  • 高维（n>80）更快
  • 像"广度碰撞"，大量样本互相作用
一句话总结：筛法 = 随机采样大量格向量 → 让向量之间互相"约简"（相加/相减变短）→ 反复迭代直到列表收敛到最短向量。用空间换时间，用概率换速度。

2. 筛法的核心思想：用大量随机样本"撞"出短向量

2.1 关键观察：两个向量相减可能更短

筛法的一切都建立在一个简单事实上：对于格中的两个向量 u 和 v，如果它们的夹角比较小（方向接近），那么 u - v 很可能比 u 和 v 都短！

||u - v||² = ||u||² + ||v||² - 2⟨u, v⟩

当 u 和 v 方向接近时，内积 ⟨u, v⟩ 很大，所以 ||u - v||² 可能远小于 ||u||² 和 ||v||²。

2.2 筛法的基本循环

所有筛法算法都遵循同一个基本循环：

1
采样（Sample）
用 Klein 采样算法或其他方法，从格中随机采样一个向量 v
2
约简（Reduce）
用列表 L 中已有的向量来约简 v：对每个 w ∈ L，如果 ||v ± w|| < ||v||，就把 v 替换为 v ± w
3
反向约简（Reduce back）
用约简后的 v 来约简列表 L 中的向量：对每个 w ∈ L，如果 ||w ± v|| < ||w||，就把 w 替换为 w ± v，并把被替换的旧 w 放回待处理队列
4
加入列表
把最终约简后的 v 加入列表 L（如果 v ≠ 0）
5
重复直到收敛
当列表 L 不再增长、且最短向量稳定时，输出 L 中最短的向量

2.3 为什么这样能找到最短向量？

这背后有一个关键的几何事实：Kabatiansky-Levenshtein 界。在 n 维空间中，最多只能放 2^{0.401n} 个两两夹角 ≥ 60° 的单位向量。

筛法的约简操作保证了：列表 L 中任意两个向量的夹角都 ≥ 60°（否则它们相减会更短，就会被约简掉）。所以列表 L 的大小有上界 2^{0.401n}。当列表"满"了之后，新采样的向量几乎总能被约简到 0——这意味着列表中已经包含了足够短的向量，最短向量就在其中！

3. AKS 筛法：理论奠基之作

2001 年，Ajtai、Kumar 和 Sivakumar 提出了第一个单指数时间 2^{O(n)} 的 SVP 算法，这就是 AKS 筛法。它的意义不在于实用（常数极大，从未被高效实现），而在于证明了筛法这个思路在理论上是可行的。

3.1 AKS 的核心设计

AKS 筛法使用多轮、多列表的结构：

  1. 采样大量（指数级）随机格向量
  2. 按长度分成若干"桶"（sublist），每个桶内的向量长度相近
  3. 在每个桶内，把方向接近的向量配对，用 u-v 生成更短的向量
  4. 把生成的短向量收集起来，进入下一轮
  5. 重复多轮，向量越来越短，最终得到最短向量
历史意义：AKS 筛法首次证明了 SVP 可以在 2^{O(n)} 时间内求解，打破了之前 2^{Θ(n log n)} 的枚举壁垒。它启发了后续所有实用筛法的设计。

3.2 AKS 的问题

  • 常数因子极大，理论上 2^{O(n)} 但实际中 2^{10n} 都不止
  • 需要维护大量列表，内存开销巨大
  • 分析复杂，参数难以调优
  • 从未被真正实现过——它是一个"存在性证明"而非实用算法

4. ListSieve / NV 筛法：第一代实用筛法

2008 年，Nguyen 和 Vidick 提出了 NV 筛法（也叫 ListSieve），首次让筛法变得"可以跑起来"。他们简化了 AKS 的多列表结构，改用单个列表 + 近似约简。

4.1 ListSieve 的流程

  1. 初始化空列表 L
  2. 采样一个随机格向量 v
  3. 用 L 中的向量约简 v：遍历 L，如果 ||v - w|| < ||v||，则 v ← v - w
  4. 如果 v ≠ 0，把 v 加入 L
  5. 重复直到 L 的大小稳定（不再增长）
  6. 输出 L 中最短的向量

4.2 和 AKS 的关键区别

AKS (2001)

  • 多轮、多列表
  • 精确配对（找最接近的向量）
  • 理论保证强
  • 常数极大，不实用

NV / ListSieve (2008)

  • 单列表、在线处理
  • 贪心约简（遍历列表依次约简）
  • 启发式，无严格证明
  • 常数合理，可实现

4.3 复杂度

NV 筛法的启发式复杂度约为时间 2^{0.415n}，空间 2^{0.208n}。虽然比 AKS 好很多，但还不够快——后续的 Gauss Sieve 和 Tuple Sieve 进一步优化了这个常数。

5. Gauss Sieve：最经典的实用筛法

2010 年，Micciancio 和 Voulgaris 提出了 Gauss Sieve，这是迄今为止最著名、最广泛实现的筛法算法。它的核心改进是双向约简：不仅用列表约简新向量，还用新向量约简列表中的旧向量。

5.1 Gauss Sieve 的完整流程

1
初始化
空列表 L，空栈 S（存放被修改后需要重新约简的向量），计数器 collisions = 0
2
取一个向量
如果栈 S 非空，从 S 中弹出一个向量 v；否则采样一个新的随机格向量 v
3
用 L 约简 v（forward reduce）
遍历 L 中的每个 w，尝试 v ← v ± w（选让 ||v|| 更小的符号），直到 v 不能再被 L 中的任何向量缩短
4
用 v 约简 L（backward reduce）
遍历 L 中的每个 w，尝试 w ← w ± v。如果 w 被修改了，把旧的 w 从 L 中移除并压入栈 S
5
加入列表或计数碰撞
如果 v = 0，说明 v 被完全约简掉了（collisions++）；否则把 v 加入 L
6
终止条件
当 collisions 达到某个阈值（如列表大小的若干倍）时，算法收敛，输出 L 中最短向量

5.2 为什么叫"Gauss"筛法？

因为约简操作的本质是高斯格基约简（Gaussian reduction）的推广：在二维中，高斯约简反复用 b₁ ← b₁ - ⌊⟨b₁,b₂⟩/||b₂||²⌉·b₂ 来缩短向量。Gauss Sieve 把这个思想推广到了高维的向量列表上。

5.3 双向约简为什么重要？

关键洞察：只做 forward reduce（用 L 约简 v）是不够的——L 中可能存在两个向量 u 和 w，它们本身可以互相约简，但因为谁也没"主动"去约简对方，就一直留在列表里。Backward reduce 确保了：每当新向量 v 加入时，会主动去"清理"列表中的旧向量，让列表始终保持"两两不可约简"的状态。这大大加速了收敛。

5.4 复杂度

Gauss Sieve 的启发式复杂度：时间 2^{0.377n}，空间 2^{0.208n}。比 NV 筛法的 2^{0.415n} 有明显提升。

7. Tuple 筛法：用更多向量组合

Gauss Sieve 每次只组合两个向量（u ± v）。一个自然的问题：能不能一次组合更多向量来获得更大的长度缩减？这就是 Tuple 筛法（元组筛法）的思想。

7.1 从 2-sieve 到 k-sieve

2-sieve（即 Gauss Sieve）：找两个向量 u, v，如果 ||u ± v|| < min(||u||, ||v||)，就用 u ± v 替换较长的那个。

3-sieve：找三个向量 u, v, w，如果 ||u ± v ± w|| < min(||u||, ||v||, ||w||)，就用这个组合替换最长的那个。

k-sieve：推广到 k 个向量的组合。

||±v₁ ± v₂ ± ... ± vₖ|| < min(||v₁||, ..., ||vₖ||) → 替换

7.2 为什么更多向量组合更好？

因为在高维空间中，三个向量的组合比两个向量的组合更有可能产生短向量。直观上，更多的向量意味着更多的"自由度"来调整方向，让组合结果更短。

trade-off：k 越大，每次组合的长度缩减越大，但找到好的 k 元组也越困难（搜索空间从 O(N²) 变成 O(Nᵏ)）。实践中 k=3 是最佳平衡点——3-sieve 比 2-sieve 快，但 4-sieve 的搜索开销已经超过了收益。

7.3 3-sieve 的复杂度

3-sieve 的启发式复杂度：时间 2^{0.338n}，空间 2^{0.189n}。比 Gauss Sieve 的 2^{0.377n} 又提升了一步。

7.4 G6K 中的实现

G6K（General Sieve Kernel）实现了高效的 3-sieve，是目前创纪录的格基约化工具。它使用分桶（bucketing）技术来加速三元组的搜索：把向量按方向哈希到桶中，只在同一个桶内搜索三元组，避免了 O(N³) 的暴力搜索。

8. LSH 加速：如何快速找到"相近"的向量

筛法的瓶颈在于：每次约简都需要在列表中找到与当前向量方向接近的向量。如果暴力遍历整个列表，每次约简需要 O(N) 时间，而 N 是指数级的 2^{0.2n}，这太慢了。

局部敏感哈希（LSH, Locality-Sensitive Hashing）解决了这个问题。

8.1 LSH 的核心思想

通俗类比

想象你在图书馆找一本书。你不会从第一排开始一本一本地翻（暴力搜索），而是先看分类号——哲学书在 B 区，计算机书在 T 区。分类号就是一个"哈希"：相似的书（主题接近）被分到同一个区域。

LSH 做的是同样的事：设计一个哈希函数，让方向接近的向量有更大概率哈希到同一个桶，方向远离的向量大概率哈希到不同桶。这样找相近向量时，只需要检查同一个桶里的向量，不用遍历全部。

8.2 角度 LSH（Angular LSH）

对于格筛法，最常用的是角度 LSH（也叫随机超平面 LSH，Charikar 2002）：

h(v) = sign(⟨a, v⟩)，其中 a 是随机高斯向量

这个哈希函数的性质：两个向量 v 和 w 的夹角为 θ 时，它们哈希值相同的概率是 1 - θ/π。夹角越小（方向越接近），同桶概率越高！

为了提高精度，通常使用多个哈希函数 + 多个哈希表：

  • 每个哈希表用一组（比如 10-20 个）随机超平面，向量的哈希值是这些超平面 sign 的组合
  • 建多个（比如 20-30 个）哈希表，每个用不同的随机超平面
  • 查询时，在所有哈希表中找与查询向量同桶的向量，取并集作为候选

8.3 LSH 带来的加速

使用 LSH 后，每次约简的候选向量数从 O(N) 降到了 N^{ρ}（ρ < 1），整体时间复杂度从 2^{0.415n} 降到了 2^{0.337n}（NV 筛法 + LSH）。这是一个巨大的提升！

LSH 的代价：
  • 需要额外的内存存储哈希表（通常是列表大小的 5-10 倍）
  • 有一定概率漏掉真正相近的向量（假阴性），但实践中通过多哈希表可以把概率压得很低
  • 哈希函数的参数（超平面数量、哈希表数量）需要仔细调优

8.4 更先进的加速技术

  • 分桶（Bucketing）：G6K 使用的技术，按向量在随机超平面上的投影排序，只比较投影接近的向量对
  • Folding：把向量折叠到一个基本域内，减少需要比较的向量数量
  • GPU/Tensor Core 加速：利用 GPU 的并行计算能力同时处理大量向量对

9.3 工程上的权衡

什么时候用枚举？

  • 维度较低（n ≤ 60-70）
  • 内存受限（枚举只用多项式空间）
  • 需要确定性保证
  • BKZ 的块内 SVP（块大小 β ≤ 60）

  • 维度较高（n ≥ 80）
  • 内存充足（筛法需要指数空间）
  • 追求最快速度
  • 高维 SVP 挑战、密码分析
  • BKZ 的大块 SVP（β > 60）

10. 最简 Python 代码实现

下面是一个教学用的 Gauss Sieve 最简实现。它省略了 LSH 加速、采样优化等工程细节，但完整保留了 Gauss Sieve 的核心逻辑。

10.1 随机采样（Klein 采样的简化版）

import numpy as np

def sample_vector(B, sigma=None):
    """
    从格 L(B) 中随机采样一个向量。
    简化版：对每个基向量系数取随机整数，偏向小系数。
    工业实现用 Klein 采样（基于 GSO 的离散高斯采样）。
    """
    n = B.shape[0]
    if sigma is None:
        sigma = n  # 采样半径
    # 随机整数系数，标准差为 sigma
    coeffs = np.round(np.random.normal(0, sigma, n)).astype(int)
    return coeffs @ B

10.2 Gauss Sieve 核心实现

def gauss_sieve(B, max_collisions=None, verbose=False):
    """
    Gauss Sieve 算法，求格 L(B) 的最短向量。
    B: n×m 的格基矩阵（n 行向量）
    返回: (最短向量, 最短长度平方, 列表大小)
    """
    n = B.shape[0]
    if max_collisions is None:
        max_collisions = 4096  # 碰撞阈值，越大结果越精确

    L = []           # 向量列表
    S = []           # 栈：存放被修改后需要重新约简的向量
    collisions = 0
    best_norm = np.inf
    best_v = None

    def reduce_vector(v, lst):
        """用列表 lst 中的向量约简 v，返回约简后的 v"""
        changed = True
        while changed:
            changed = False
            for w in lst:
                # 尝试 v - w 和 v + w，选更短的
                v_minus = v - w
                v_plus = v + w
                norm_v = np.dot(v, v)
                norm_minus = np.dot(v_minus, v_minus)
                norm_plus = np.dot(v_plus, v_plus)
                if norm_minus < norm_v:
                    v = v_minus
                    changed = True
                elif norm_plus < norm_v:
                    v = v_plus
                    changed = True
        return v

    iteration = 0
    while collisions < max_collisions:
        iteration += 1

        # 步骤1: 取一个向量（优先从栈取，否则新采样）
        if S:
            v = S.pop()
        else:
            v = sample_vector(B)

        # 步骤2: 用 L 约简 v (forward reduce)
        v = reduce_vector(v, L)

        # 步骤3: 检查是否被约简为 0
        if np.all(v == 0):
            collisions += 1
            if verbose and collisions % 500 == 0:
                print(f"碰撞 {collisions}/{max_collisions}, 列表大小 {len(L)}")
            continue

        # 步骤4: 用 v 约简 L 中的向量 (backward reduce)
        new_L = []
        for w in L:
            w_minus = w - v
            w_plus = w + v
            norm_w = np.dot(w, w)
            norm_minus = np.dot(w_minus, w_minus)
            norm_plus = np.dot(w_plus, w_plus)
            if norm_minus < norm_w:
                S.append(w)  # 旧 w 需要重新约简
                # 不把 w 加入 new_L（它被 v 替换了位置）
            elif norm_plus < norm_w:
                S.append(w)
            else:
                new_L.append(w)
        L = new_L

        # 步骤5: 把 v 加入列表
        L.append(v)

        # 更新最短向量
        norm_v = np.dot(v, v)
        if norm_v < best_norm:
            best_norm = norm_v
            best_v = v.copy()

    return best_v, best_norm, len(L)

# 一个简单的二维格
B = np.array([[3, 1],
              [1, 4]])

np.random.seed(42)
v, norm, list_size = gauss_sieve(B, max_collisions=200)
print("最短向量:", v)
"最短长度平方:", norm)
print("最终列表大小:", list_size)
# 最短向量: [1 0] 或 [-1 0]，长度平方 = 5（和枚举结果一致）
注意：这是教学实现，有几个简化：
  • 采样用简单的随机整数系数，工业实现用 Klein 离散高斯采样
  • 约简是暴力遍历列表，工业实现用 LSH/分桶加速
  • 没有处理数值稳定性和高维优化
  • 高维下会非常慢（没有 LSH 加速）
但核心思想——采样、双向约简、碰撞计数、列表收敛——是完全一致的。

11. 工业界使用的库

实际使用中，你几乎不会自己实现筛法。下面是目前最主流的筛法库：

G6K
C++ / Python

General Sieve Kernel，目前最强的格筛法库。由 Albrecht、Ducas 等人开发，实现了高效的 3-sieve、分桶加速、Pump 机制。多次打破 SVP 挑战纪录，是高维格基约化的首选。

GitHub: fplll/g6k

fplll
C++

最权威的格基约化库。虽然以枚举/BKZ 闻名，但也包含了筛法实现（通过 G6K 集成）。是 SageMath 的默认后端。

GitHub: fplll/fplll

G6K-GPU-Tensor
C++ / CUDA

G6K 的 GPU 加速分支，利用 NVIDIA Tensor Core 加速筛法中的向量内积计算。在支持的 GPU 上可获得数倍加速。

GitHub: mfkiwl/g6k-gpu-tensor

g6k-rs
Rust

G6K 的 Rust 重实现，提供 LLL/BKZ、筛法、CPU 加速。内存安全，适合需要现代工具链的项目。

Crates: g6k-rs

SageMath
Python

开源数学软件，内置 fplll 和 G6K 的封装。可以用一行代码调用筛法，是研究和教学最方便的工具。

官网: sagemath.org

fpylll
Python

fplll 的 Python 封装，可与 G6K 配合使用。方便在 Python 中进行格算法实验和原型开发。

安装: pip install fpylll

11.1 快速上手：G6K 示例

from g6k import Siever
from fpylll import IntegerMatrix, LLL

# 创建一个随机格基
A = IntegerMatrix.random(80, "qary", k=40, q=2**20)
LLL.reduction(A)

# 创建筛法器
siever = Siever(A)

# 运行筛法（默认 3-sieve + 分桶加速）
siever.sieve(10)  # 10 轮迭代

# 获取数据库中最短的向量
best = siever.best_vector()
print("最短向量长度:", best.norm())

12. 总结与延伸阅读

核心要点回顾

  1. 筛法是什么：随机采样大量格向量，让它们互相约简（相加/相减变短），反复迭代直到列表收敛到最短向量
  2. 几何原理：两个方向接近的向量相减会更短；列表中向量两两夹角 ≥ 60° 时列表大小有上界
  3. AKS (2001)：理论奠基，证明 2^{O(n)} 可行，但不实用
  4. Gauss Sieve (2010)：最经典的实用筛法，双向约简是关键
  5. Tuple Sieve：3-sieve 比 2-sieve 更快，k=3 是最佳平衡点
  6. LSH 加速：用角度局部敏感哈希快速找到方向接近的向量，时间降到 2^{0.292n}
  7. 枚举 vs 筛法：低维用枚举（省空间），高维用筛法（省时间），现代工具混合使用
  8. 工业实现：G6K（最强筛法）、fplll（枚举+BKZ）、SageMath（易用）

延伸阅读

  • Ajtai, Kumar, Sivakumar (2001) — "A sieve algorithm for the shortest lattice vector problem"（AKS 原始论文，STOC）
  • Nguyen & Vidick (2008) — "Sieve algorithms for the shortest vector problem are practical"（NV 筛法）
  • Micciancio & Voulgaris (2010) — "Faster exponential time algorithms for the shortest vector problem"（Gauss Sieve）
  • Becker, Ducas, Gama, Laarhoven (2016) — "New directions in nearest neighbor searching with applications to lattice sieving"（3-sieve + LSH）
  • Albrecht et al. (2019) — "The General Sieve Kernel and New Records in Lattice Reduction"（G6K 论文）
  • Laarhoven (2015) — "Sieving for shortest vectors in lattices using angular locality-sensitive hashing"（LSH 筛法）

未来趋势

筛法目前是高维 SVP 的最快算法，但仍在快速发展：

  • GPU/Tensor Core 加速：利用并行硬件进一步加速
  • 量子筛法：结合 Grover 搜索获得多项式级量子加速（目前仍为理论）
  • 混合算法：枚举和筛法的深度融合（如 G6K 的 Pump）
  • 理想格/模格专用筛法：利用格的代数结构进一步加速
